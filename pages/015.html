内网服务器如何访问公网

背景

现有一台服务器（记为S），一台本地终端（记为L）。服务器无法访问公网。但具有局域网ip a.b.c.d。 常规的上机方式为。L连接局域网，通过命令进入服务器。

ssh user@a.b.c.d

但即使这样连接成功，服务器依然无法访问公网。当执行

dnf install xxx
pip install xxx
wget xxx

这类命令时会报错。

看上去，我们需要一台能同时与局域网和公网通信的设备，充当流量的中介。服务器可以把所有请求发给这台设备，设备与公网通信，将返回的信息转发给服务器即可。

我们手上的L正是这样一台设备。

具体操作

在L的终端上敲命令：

ssh -R 7890:127.0.0.1:7891 user@a.b.c.d

进入服务器S，然后在S的终端上敲：

export http_proxy=127.0.0.1:7890
export https_proxy=127.0.0.1:7890

此时，S和公网之间的通信渠道就已经介由L打通了。

但要想用得顺利，还有以下环节必须保证。

本地代理

之前在L上执行的：

ssh -R 7890:127.0.0.1:7891 user@a.b.c.d

命令的意思是反向打通一个ssh隧道。远程设备S的7890端口的流量会转发到L的7891端口。可见这个命令的127.0.0.1代表的是L。

那么问题来了，L上得有个进程监听7891端口接收这份流量，然后转发到公网。这个进程就是代理。

因此你需要保证L正在运行一个代理，如果你已经有一些软件用来科学上网，就可以直接启动，不需要再下软件了。

如果没有下载过类似软件，可以找Clash Verge Rev， sing-box之类的开源代理软件。注意，代理软件并不一定是科学上网软件，但科学上网软件一般都可以充当代理。

下面问题又来了。建立反向隧道时，输入的7891端口是自定义的，如果代理软件可以指定端口，我把它调成监听7891即可。如果要用科学上网工具，这些软件一般都是无脑连接的，根本不知道它监听哪个端口。下面是一种解决方法，供参考：

首先，我打开通过任务管理器-性能，右上角的三个点，打开资源监视器。进入网络标签页。往下翻到TCP连接列表。 通过软件名称，就能找到进程的PID和监听的端口。通常可能会有多个。例如我这里的信息大致为显示：

  Proto  Local Address          Foreign Address        State           PID
  TCP    0.0.0.0:19822          0.0.0.0:0              LISTENING       7492
  TCP    127.0.0.1:19827        0.0.0.0:0              LISTENING       7492
  TCP    127.0.0.1:19828        0.0.0.0:0              LISTENING       7492
  TCP    [::]:19822             [::]:0                 LISTENING       7492

# 事实上，上述命令是通过netstat -aon|findstr 7492命令获得的，但你在资源监视器里看到的内容和这个差不多。

有19822，19827，19828三个端口被被进程7492占用。同时19822占用IPV4和IPV6两个协议。通常我们用IPV4，以及监听本地回环(127.0.0.1)的连接。这样一来，可选范围就收敛到了19827和19828。

不妨试试谁能跑通：

curl.exe -x http://127.0.0.1:19827 https://www.baidu.com
# 报错： curl: (56) CONNECT tunnel failed, response 405
curl.exe -x http://127.0.0.1:19828 https://www.baidu.com
# 成功：返回内容为一个HTML文本

这就说明19828是正确的端口，可以用来转发流量。

这样一来，建立ssh隧道时，我们改成

ssh -R 7890:127.0.0.1:19828 user@a.b.c.d

一切就对了。

（题外话：有没有感觉像是在各个设备之间插管子，是的，就是这么简单，把管子插对即可）

服务器设置

如前文所言，S的7890端口现在与L的19828端口连上了。因此只要在服务器上敲命令，就能直接上公网。

但不幸的是，照常执行命令，例如

sudo dnf install slurm

依然无法连接。原因在于我们没有显式地把流量转发到本机的7890端口。

因此首先需要设好环境变量。

export http_proxy=127.0.0.1:7890
export https_proxy=127.0.0.1:7890
export all_proxy=socks5://127.0.0.1:7890 #可选

然后在执行命令时，声明使用代理即可，以下是几个例子：

pip install --proxy http://127.0.0.1:7890 XXX
sudo dnf -E install XXX

大部分软件都有一个选项用于声明使用代理。只要明确把流量转发到7890端口上即可。

如果仅是为了测试网络是否畅通，依然可以用curl:

curl -x http://127.0.0.1:7890 https://www.baidu.com

如果返回一个HTML文档，就说明网络跑通了。剩下的事情就是指挥具体软件。

Tips

  • 之前的 export http_proxy=127.0.0.1:7890命令只生效于当前shell。可以写进.bashrc作持久化。
  • 7890是代理软件常用端口，就像ssh默认用22，postgresql默认用5432一样。这只是个习惯性动作，其实完全可以你自由发挥。只要保证各个环节的端口对上号即可（想象一下接水管）。
  • 注意到上面的命令，我一会儿用curl一会用curl.exe，这是因为前者是linux的命令，后者是powershell上的命令。同时需要注意的是，powershell有一些反人类的默认行为，powershell上输入curl时，也能工作，但实际执行的是Invoke-WebRequest这个命令，因此你会发现动不动就报错。实际上，curl.exe才是真正的curl。
